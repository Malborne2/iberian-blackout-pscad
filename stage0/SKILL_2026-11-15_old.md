# PSCAD through the `pscad` MCP server

Every `pscad_*` tool drives the real PSCAD 5.1.0 (Educational) on this machine. There is no dry run.
Coordinates in every tool are **grid units** (the `.pscx` file stores grid × 18).

**The one rule: never assume, always read back.** PSCAD accepts wrong coordinates, wrong parameter
values and wires that touch nothing, and reports success. After every action, read the result with
the tool named in the procedure. If a read-back differs from what you expected, stop and fix that
before doing anything else.

Each fact below is tagged: **[API]** checked against the installed `mhi.pscad` 3.1.3 documentation;
**[seen]** observed on this machine in an earlier session; **[untested]** not yet tried — test it on
a throw-away project first and record the outcome in `RUNLOG.md`.

## 0. Setup (once)

1. The server lives in `C:\GitHub\PSCAD-MCP`. It must be registered with the client, e.g. in the
   project's `.mcp.json`:
   `{"mcpServers": {"pscad": {"command": "python", "args": ["-m", "pscad_mcp.server"], "cwd": "C:\\GitHub\\PSCAD-MCP"}}}`
2. **Extra tools.** The base server has 45 tools and lacks port reading, buses, node labels, canvas
   size, copying, definitions and node counts. `ext.py` next to this file adds them. Install: copy
   it to `C:\GitHub\PSCAD-MCP\pscad_mcp\ext.py`, add `from . import ext  # noqa` just above
   `def main()` in `pscad_mcp\server.py`, restart the server. Tools marked ⊕ below come from `ext.py`.
   (Installed on 2026-11-15; the server now lists 68 tools.) If a ⊕ tool is missing from your tool list, **stop and ask the user to install `ext.py`**; do not
   work around it by guessing coordinates or editing the `.pscx` by hand.
3. **Self-test of the ⊕ tools** [untested]: on the repo's `demo_project/mcp_demo.pscx`, call
   `pscad_get_ports` on the resistor, `pscad_get_bounds`, `pscad_get_canvas_settings`,
   `pscad_get_messages_structured`, then build and call `pscad_get_build_dimensions`. Record any
   tool that errors in `RUNLOG.md` and tell the user.

## 1. Which tool for which job

| Job | Tool |
| --- | --- |
| Start | `pscad_connect` → check `needs_login` → `pscad_status` |
| Open / list / close projects | `pscad_load(paths)`, `pscad_list_projects`, `pscad_unload_project` |
| New project | `pscad_create_project(name, folder, "case")` |
| Run settings | `pscad_get_project_parameters`, `pscad_set_project_parameters` |
| What is on a canvas | `pscad_list_canvas_objects` ⊕ (fast), `pscad_find_component`, `pscad_list_components` (slow: reads every parameter) |
| Place a component | `pscad_add_component(project, library, name, canvas, x, y, orient, parameters)` |
| **Where are its ports** | `pscad_get_ports` ⊕ |
| Its box | `pscad_get_bounds` ⊕ |
| Parameters | `pscad_get_component_parameters`, `pscad_set_component_parameters`, legal values: `pscad_get_parameter_range` ⊕ |
| Wire | `pscad_create_wire(project, vertices, canvas)` |
| Bus | `pscad_create_bus` ⊕ |
| Connect far-apart points | `pscad_create_node_label_pair` ⊕ |
| Canvas size, free space | `pscad_get_canvas_settings` ⊕, `pscad_set_canvas_settings` ⊕, `pscad_find_empty_rect` ⊕ |
| Copy | `pscad_clone_component` ⊕, `pscad_copy_region` ⊕ + `pscad_paste` ⊕ |
| Definitions / modules | `pscad_list_definitions` ⊕, `pscad_copy_definition` ⊕, `pscad_export_definition_xml` ⊕, `pscad_rename_definition` ⊕ |
| Build | `pscad_build_project` → `pscad_get_messages_structured` ⊕ → `pscad_get_build_dimensions` ⊕ |
| Run | `pscad_run_project(name, wait=False)` → poll `pscad_get_run_status`; log: `pscad_get_run_output` ⊕ |
| Results | `pscad_find_output_file` → `pscad_list_output_channels` → `pscad_get_trace_window` ⊕ / `pscad_get_trace_data` / `pscad_export_traces_csv` ⊕ |
| Save | `pscad_save_project` (after every successful step) |

Inside a module: pass the module's **definition name** as `canvas` (e.g. `canvas="RES_Plant"`)
[API: `Project.canvas(name)` takes a definition name].

## 2. Procedures

### P1. Start of every session
1. `pscad_connect`. If `needs_login: true`, ask the user to log in (never ask for or type passwords yourself unless the user offers them).
2. `pscad_list_projects`. **Do not `pscad_load` a project that is already listed** — it raises a modal dialog and every later call hangs [seen].
3. `pscad_get_project_parameters`: confirm `PlotType` is `"PSOUT"`; if not, set it and read it back. A wrong value gives a successful run with no output file [seen].

### P2. Place and wire one component (the core loop)
1. **Find room.** `pscad_find_empty_rect(width, height, near)` with 2 grid units of margin on each side.
2. **Place.** `pscad_add_component(...)`. Keep the returned `iid`.
3. **Read ports.** `pscad_get_ports(iid)`. Write down each port's `x`, `y`, `dim`, `type`.
4. **Check the box.** `pscad_get_bounds([iid])`; compare with `pscad_list_canvas_objects`. No other component, wire or bus may lie inside or touch the box, except where you intend a connection. Overlaps connect silently [seen].
5. **Wire.** `pscad_create_wire` from the exact port coordinate to the exact target coordinate. Rules:
   - A wire must **end on** a port, never pass through a component [seen].
   - A wire that **crosses a bus or another wire's endpoint connects to it** [seen]. Route around, or use `pscad_create_node_label_pair`.
   - Two ports at the same coordinate are already connected; a zero-length wire raises `At least 2 points are required` — skip it [seen].
   - Only connect ports of the same `dim`. A dimension-1 port tied to a dimension-3 node gives `Signal '...' dimension mismatch -> 1 != 3` [seen].
   - Data (control) wires and electrical wires look the same. Check `type` of both ends: output → input for signals; electrical ↔ electrical.
6. **Build and read messages** (P6). One component at a time until a pattern is proven; then at most three per build.
7. `pscad_save_project`.

To change orientation: delete and re-add with another `orient` (0–3 rotations, 4–7 mirrored), then
read the ports again. Do not calculate rotated port positions yourself.

### P3. Parameters
1. `pscad_get_component_parameters(iid)` first. Use the **exact** key names it returns. Parameter names are internal symbols, not the dialog captions (a machine port or parameter called `telect` is not necessarily a terminal voltage — check PSCAD's help or a shipped example before deciding what it is).
2. For a choice parameter call `pscad_get_parameter_range` and use one of the returned values. On this machine some choices accept only the **index**, some the label; `PlotType` reads back as a label but is stored as an index [seen].
3. Values with units are strings: `"50.0 [ohm]"`, `"400 [kV]"`.
4. Set, then read back with `pscad_get_component_parameters` and compare. `set_parameters` performs no validity check [API]; a value outside the allowed range may be silently ignored or clamped inside the model (a negative `PO` on `fixed_load` drew zero power [seen]).
5. `fixed_load`: `PO`, `QO` are **per phase**; `VBO` is line-to-neutral [seen].

### P4. Buses and labels
- `pscad_create_bus(vertices)`, then name it (P3). Two buses with the same name fail the build: `Multiple buses with the name 'Bus' detected` [seen]. Whether name and base kV can be set through the tool is [untested]; if the parameter list comes back empty, ask the user to name the bus in the GUI.
- `pscad_create_node_label_pair(..., electrical=True)` for a power connection across the sheet; `electrical=False` for a control signal. Use the label the tool returns.

### P5. Record a signal
1. Give the measuring component (multimeter, voltmeter, machine output…) a signal name in its own parameters.
2. Place `master:datalabel` with `Name` = that signal name.
3. Place `master:pgb`; wire datalabel port → pgb input port (read both with `pscad_get_ports`).
4. Wiring a pgb straight to a component's output port produced no channel [seen]; go through a named signal.
5. After a run, find the channel with `pscad_list_output_channels` — its `path` contains the pgb name.

### P6. Build and verify
1. `pscad_get_messages_structured(project)` → note `total` (call it N0).
2. `pscad_build_project(project)`. Its return value says nothing about success [seen].
3. `pscad_get_messages_structured(project, status="error", skip=N0)`. Zero errors = built. For each error use `link` (component iid) to find the culprit.
4. Also read `status="warning"`. Treat as errors: `short circuit`, `Open circuit`, `floating`, `Unresolved`, `source contention`, `below range`, `above range`.
5. `pscad_get_build_dimensions` → record `NODES`, `NPAGES`, `SUBSYS` in `RUNLOG.md`. Educational limits: 200 nodes, 64 module pages, 1 subsystem.
6. Failed build and **no** new messages → the error is only in PSCAD's Build Messages pane. Ask the user to read it out.

### P7. Run and read results
1. Set `time_duration` (s), `time_step` (µs), `sample_step` (µs), `PlotType="PSOUT"`; read back.
2. Short runs (< 1 min wall-clock): `pscad_run_project(name, wait=True)`. **Long runs: `wait=False`**, then `pscad_get_run_status` every few minutes until status is no longer `"Build"`/`"Run"`. A blocking call that outlives the client's tool timeout loses the session.
3. `pscad_get_run_output` — look for EMTDC warnings and errors. "stopped unexpectedly" with no log → see `C:\GitHub\PSCAD-MCP\docs\TROUBLESHOOTING.md` (Windows variable `NoDefaultCurrentDirectoryInExePath`).
4. `pscad_find_output_file` → check the file's modification time is after the run started (a stale file looks like a result [seen]).
5. Gate checks: `pscad_get_trace_window(path, channel, t_start, t_end)`. Plots and comparisons: `pscad_export_traces_csv`, then a Python script.

### P8. Modules (one definition, many instances)
A module is a component with its own canvas. Rules for this project: **flat** (no module inside a
module), built and proven in a small test-bench project first.
1. **Creating the empty module shell (ports + parameter form) cannot be done with these tools.** Ask the user to create it in the GUI (Create New Component wizard, "page module") with the port list and parameter list given in the plan. This is a planned manual step, not a failure.
2. Fill it: every placement/wiring call with `canvas="<definition name>"`, following P2.
3. Test bench passes its gate → `pscad_copy_definition(from_project=bench, definition, to_project=main)`.
4. Place instances: `pscad_add_component(project=main, library=main, name=definition, ...)`, then `pscad_get_ports` on each instance.
5. How instance parameters are passed in `parameters={...}` is [untested] — try on the test bench with two instances and confirm each instance behaves differently.

### P9. Reuse a working group from a PSCAD example
Shipped examples: `C:\Users\Public\Documents\PSCAD\5.1.0\Examples\`. For machine + exciter + governor
use `sync_machines\sync_exciter_governor.pscx`.
1. `pscad_load` the example. `pscad_list_canvas_objects` + `pscad_get_ports` + `pscad_get_component_parameters` on each part: record how each port is wired and every parameter. **This record is the specification** — copy it, do not improve it.
2. `pscad_copy_region` around the group, `pscad_paste(mode="rename")` on the target canvas [untested].
3. Build the pasted group alone with a source on its terminals before changing any parameter.
4. `pscad_unload_project` the example **without saving**.

### P10. Snapshots (start many cases from one initialised state)
Project parameters [API names; behaviour untested]: `SnapType` (0 none, 1 single), `SnapTime` (s),
`snapshot_filename` to write one; `StartType=1` and `startup_filename` to start from one.
Test on the demo project: run 0.2 s with a snapshot at 0.1 s, restart from it, check the trace continues.

### P11. Canvas too small
`pscad_get_canvas_settings` → `pscad_set_canvas_settings(parameters={"size": "100X100"})` → read
`grid_size` back. Do this **before** placing anything: components outside the canvas are moved onto
its corner, on top of each other, at the next save [seen].

### P12. Editing the `.pscx` file directly — last resort
Only for bulk numeric changes with no tool equivalent. `pscad_save_project` → `pscad_unload_project`
→ edit → `pscad_load` → build. Never edit while loaded: PSCAD overwrites the file from memory [seen].
Make all edits in one pass; never apply text offsets collected before an earlier edit [seen].

## 3. Symptom → cause → what to do

| Symptom | Likely cause | Do |
| --- | --- | --- |
| Every tool call hangs | Modal dialog open in PSCAD (login, "already loaded", save prompt) | Ask the user to look at the PSCAD window |
| Build fails, no messages | Hard error shown only in the GUI | Ask the user for the Build Messages text |
| `dimension mismatch -> 1 != 3` | 1-conductor port on a 3-phase node; or a component's body overlapping a wire/port | `pscad_get_ports` on the component in `link`; check bounds for overlap |
| `source contention` | Two outputs on one signal, often two components at the same coordinate | `pscad_list_canvas_objects`, look for identical bounds |
| `Input port '...' is floating` | Signal input not wired | Wire it (P2) |
| `Position is exactly on another instance` | Two components at the same x/y | Move one |
| Run fine, no `.psout` | `PlotType` not `PSOUT` | P1 step 3 |
| Results unchanged after an edit | Stale output file, or the edit did not apply | Check file time; read the parameter back |
| Machine terminal voltage sags / drifts | Machine not initialised, or no exciter | Follow the example's start-up exactly (P9). **Never change machine reactances to fix it** |
| Node limit / module limit error | Educational limits | Report the numbers; do not simplify the model on your own |

## 4. When to stop and ask the user

- A ⊕ tool is missing, or a tool errors twice in the same way.
- A build fails with no messages, or any call hangs.
- A module shell must be created or changed (ports, parameters).
- Anything marked [untested] behaves differently from what is written here — report what you saw so this file can be corrected.
